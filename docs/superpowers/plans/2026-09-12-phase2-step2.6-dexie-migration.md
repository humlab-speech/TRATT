# Phase 2 Step 2.6 (Dexie 0.6 migration) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate LOCAL mode's IndexedDB persistence from `local_data` (a flat, single-implicit-session table) to a new `bundles` table keyed by `[bundleId+name]`, moving the existing session into `bundle-1`. Fix a prerequisite safety bug first: IndexedDB open failures are currently silently swallowed, which would make this migration's own "export before upgrade" safety net meaningless if it ever needed to fire.

**Architecture:** `onlineMode`/`demoMode`/`urlMode` are untouched — they keep using `online_data`/`demo_data`/`url_data` exactly as today. Only LOCAL mode's persistence changes. The new `bundles` table mirrors today's `local_data` row shape (`name` ∈ `{options, annotation, logs, importOptions}`) but adds `bundleId` to the key, so each of today's 4 save/load functions gets a minimal per-mode branch rather than a redesign. The existing `local_data` rows are **copied, not deleted**, by the upgrade — a conservative extra safety margin on top of the explicit pre-upgrade database export, at negligible cost (a few KB of vestigial rows). `DEFAULT_BUNDLE_ID` (from `local-bundle-collection.ts`) is the only bundle id ever used today, matching every prior step's "one bundle until 2.7" scope — but the interface takes a real `bundleId` parameter throughout, not a hardcoded constant, so 2.7 doesn't need to touch this layer again.

**Tech Stack:** Dexie (`^4.0.11`, already used), `dexie-export-import` (`^4.1.4`, already a dependency and already wired for the pre-0.4 legacy backup path — extending its trigger condition, not adding new usage).

**Spec:** `docs/superpowers/specs/2026-09-10-workbench-conversion-design.md` (see the "Finding (2026-09-11, during 2.6 planning)" section — the IndexedDB open-failure bug this plan's Task 1 fixes as a prerequisite for the migration's safety net to mean anything).

## Global Constraints

- `onlineMode`/`demoMode`/`urlMode` and their `online_data`/`demo_data`/`url_data` tables: zero changes.
- `local_data`'s existing rows are copied into `bundles`, never deleted by this migration.
- The new `bundles` table's compound key is `[bundleId+name]` — each row is `{ bundleId, name, value }`, mirroring today's `{ name, value }` shape with one added field. This was an explicit design decision (compound key over one-row-per-bundle-with-nested-JSON) to minimize the rewrite of the existing granular save/load functions.
- Every new LOCAL-mode read/write function takes a real `bundleId: string` parameter — never hardcodes `DEFAULT_BUNDLE_ID` internally — even though every current call site passes that constant (only one bundle exists until step 2.7).
- The migration must be tested against a real seeded v0.5 database fixture (this is the "Phase 0 leftover" the original plan deferred all the way from its first defect-fixing phase — this is where it finally gets built and exercised).

import { TrattDatabase } from './tratt-database';

describe('TrattDatabase — v0.5 to v0.6 migration', () => {
  const DB_NAME = 'migration-test-db';

  afterEach(async () => {
    await Dexie.delete(DB_NAME);

  it('moves an existing local_data session into the bundles table under DEFAULT_BUNDLE_ID', async () => {
    // Seed a v0.5 database directly with Dexie, bypassing TrattDatabase's own
    // (now-v0.6) schema, to simulate a real user's existing database.
    const seedDb = new Dexie(DB_NAME);
    seedDb.version(0.5).stores({
      demo_data: '&name, value',
      online_data: '&name, value',
      local_data: '&name, value',
      url_data: '&name, value',
      app_options: '&name, value',

    await seedDb.open();
    await seedDb.table('local_data').bulkPut([
      { name: 'options', value: { currentEditor: 'Dictaphone Editor', comment: 'seeded comment' } },
      { name: 'annotation', value: { levels: [], links: [] } },
      { name: 'logs', value: [{ type: 'test', timestamp: 123 }] },
      { name: 'importOptions', value: { someOption: true } },
    ]);
    seedDb.close();

    // Now open with TrattDatabase, which should trigger the 0.5 -> 0.6 upgrade.
    const db = new TrattDatabase(DB_NAME);
    await db.init();

    const bundleOptions = await db.table('bundles').get([DEFAULT_BUNDLE_ID, 'options']);

    expect(originalOptions?.value).toEqual({ currentEditor: 'Dictaphone Editor', comment: 'seeded comment' });

    seedDb.close();

    const db = new TrattDatabase(DB_NAME);
    await db.init();
    db.close();

private upgradeToDatabaseV6 = async (tr: Dexie.Transaction) => {
  const localDataTable = tr.table('local_data');
  const bundlesTable = tr.table('bundles');
  const rows = await localDataTable.toArray();
  for (const row of rows) {

  }
};
