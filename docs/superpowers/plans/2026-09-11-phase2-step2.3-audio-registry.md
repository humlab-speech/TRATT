# Phase 2 Step 2.3 (Audio registry) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `AudioService` a `Map<bundleId, AudioManager>` registry and a `current` accessor that resolves against the currently-selected bundle, replacing the array-based `_audiomanagers[0]` access pattern. Deprecate the legacy `audioManager` getter and make it throw in dev builds when there's no resolvable current manager, so stale array-index assumptions surface loudly. This is infrastructure only — the ~7-file sweep of call sites still using the old pattern is step 2.4's job, not this one.

**Architecture:** `AudioService` currently has zero NgRx awareness (`constructor(private http: HttpClient) {}`) and stores managers in a plain array, deduped by filename. This step adds a `selectSelectedBundleId` selector (composing off step 2.1/2.2's `selectLocalMode`) and injects `Store` into `AudioService` so `current` can resolve reactively. Because `selectedBundleId` is always `DEFAULT_BUNDLE_ID` today (nothing changes it until step 2.7's multi-bundle UI lands), no mode-branching is needed — every session, regardless of login mode, registers and resolves under the same constant key today. This makes the change behavior-preserving now while wiring the exact mechanism step 2.7 will exercise.

**Tech Stack:** `@ngrx/store`'s `selectSignal` (Angular signals), matching `annotation.store.service.ts`'s established pattern for new state.

**Spec:** `docs/superpowers/specs/2026-09-10-workbench-conversion-design.md` (plan §2.5: `AudioService` gains a `Map<bundleId, AudioManager>` and a `current` accessor; the legacy `audioManager` getter is deprecated and throws in dev when there's no selection).

## Global Constraints

- No behaviour change for the current single-bundle case — `current` and the legacy `audioManager` getter must resolve to the exact same manager the old `audiomanagers[0]` access did, for every existing consumer that isn't touched by this step.
- The `audiomanagers` plural getter (array-shaped, consumed by 5 files doing `audiomanagers[0]` — out of scope for this step, deferred to 2.4) must keep returning an array with the single manager at index 0, unchanged in shape.
- `onlineMode`/`demoMode`/`urlMode` sessions also use `AudioService` (it's not mode-specific) — they must keep working identically, registering and resolving under the same constant key as LOCAL mode today.
- Follow the existing throw-on-uninitialized-access idiom already used in `TrattDropzoneService.audioManager`/`.oaudiofile` (`apps/tratt/src/app/core/component/tratt-dropzone/tratt-dropzone.service.ts:83-91`) for the deprecated getter's throw behavior; there is no existing `isDevMode()`/`environment.production`-gated throw pattern in this codebase to copy instead — this step establishes it, guarded by Angular's `isDevMode()`.

- [ ] **Step 8: Rewrite `AudioService`**

```ts
import { HttpClient } from '@angular/common/http';
import { EventEmitter, Injectable, isDevMode } from '@angular/core';
import { TaskInputOutputDto } from '@octra/api-types';
import { downloadFile } from '@tratt/ngx-utilities';
import { SubscriptionManager } from '@tratt/utilities';
import { AudioManager } from '@tratt/web-media';
import { Store } from '@ngrx/store';
import { Subject, Subscription } from 'rxjs';
import { selectSelectedBundleId } from '../../store/login-mode/annotation/annotation.selectors';

@Injectable()
export class AudioService {
  public missingPermission = new EventEmitter<void>();
  private subscrmanager: SubscriptionManager<Subscription> =
    new SubscriptionManager<Subscription>();
  private afterloaded: EventEmitter<any> = new EventEmitter<any>();

  private _audiomanagers = new Map<string, AudioManager>();
  private selectedBundleId = this.store.selectSignal(selectSelectedBundleId);

  get audiomanagers(): AudioManager[] {
    return Array.from(this._audiomanagers.values());
  }

  private _loaded = false;

  get loaded(): boolean {
    return this._loaded;
  }

  get current(): AudioManager | undefined {
    return this._audiomanagers.get(this.selectedBundleId());
  }

  /** @deprecated Use `current` — throws in dev builds when there is no resolvable manager for the current selection, instead of silently returning undefined/wrong data. */
  get audioManager(): AudioManager {
    const manager = this.current;
    if (manager === undefined && isDevMode()) {
      throw new Error(
        'AudioService.audioManager accessed with no manager registered for the current selection — use AudioService.current and handle the undefined case.',
      );
    }
    return manager as AudioManager;
  }

  constructor(
    private http: HttpClient,
    private store: Store,
  ) {}

  // ...loadAudio unchanged except its internal call site (see Step 9)...

  public registerAudioManager(bundleId: string, manager: AudioManager) {
    if (manager !== undefined) {
      const existing = this._audiomanagers.get(bundleId);
      if (existing !== manager) {
        this._audiomanagers.set(bundleId, manager);
        this.subscrmanager.add(
          manager.audioMechanism!.missingPermission.subscribe(() => {
            this.missingPermission.emit();
          }),
        );
      }
    }
  }

  public async destroy(disconnect = true) {
    for (const audioManager of this._audiomanagers.values()) {
      await audioManager.destroy(disconnect);
    }
    this._audiomanagers.clear();
    this.subscrmanager.destroy();
  }
}
```
