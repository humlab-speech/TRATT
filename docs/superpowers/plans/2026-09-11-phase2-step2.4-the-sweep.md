# Phase 2 Step 2.4 (The sweep) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace every remaining `AudioService.audiomanagers[0]` / `.audioManager` (deprecated, array-index-based) access with `.current` (bundle-aware, from step 2.3), across the whole app. Tranched by directory per the original plan's own strategy (defensive/dev-throw sites first, then effects with a real bug fix, then editors, then modals/services, then the two large page components) — one commit per tranche, low risk per site, high volume.

**Architecture:** No new production capability — `AudioService.current` already exists (step 2.3). This step only changes *call sites* to use it instead of the deprecated array-index pattern. `Category B` (raw `currentSession` reads bypassing step 2.1's fixed chokepoints) was re-verified during planning and found **already fully resolved** — no action needed, dropped from this plan's scope.

**Tech Stack:** No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-10-workbench-conversion-design.md` (plan §5, step 2.4: "Roughly 200 call sites, in tranches by directory... one commit each. Most become `audio.current`; the ones that must not guess (export, bug report, ASR effects) take an explicit `bundleId`." — see also the "Notes carried forward into step 2.4" section for step 2.3's findings this plan directly implements).

## Global Constraints

- No behaviour change for the current single-bundle case — `.current` resolves to the exact same manager `.audiomanagers[0]` did today (verified structurally in step 2.3's final review).
- Editors (`trn-editor`, `2D-editor`, `dictaphone-editor`, `linear-editor`) each do exactly ONE `this.audioManager = this.audio.audiomanagers[0]` assignment on init, then use the resulting **local field** throughout the rest of the file — only that one assignment line needs to change per editor; the local-field reads that follow are not `AudioService` accesses and are out of scope.
  - **Correction (final whole-branch review, post-2.4):** this was false for `trn-editor.component.ts` — it also had 4 direct `this.audio.audiomanagers[0]` reads elsewhere in the file, bypassing the local field, which the sweep missed and a follow-up fix wave had to close. Verify this assumption per-file rather than assuming it holds uniformly (relevant for step 2.7).
- Sites gated by `if (state.application.mode === LoginMode.ONLINE)` (or component-level online-only guards) that read `onlineMode.*`/`state.onlineMode.*` directly are explicitly **out of scope** — this whole bundle-collection refactor only touches LOCAL mode.
- `onlineMode`/`demoMode`/`urlMode` untouched, as always.
