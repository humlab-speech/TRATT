TRATT conversion plan
Implementation plan · 10 Sept 2026

Converting TRATT from a two-page workflow into a single-page workbench: a bundle collection on the left, the existing editors on the right, one pipeline applied across all loaded media, and a capacity indicator that tells the user what the machine can hold. Angular stays. Six phases, 9–13 weeks, each one shippable.

The one finding that shapes everything

The pipeline is not a service the UI calls. It is orchestrated inside login.component.ts as imperative component state — this.transcription and this.translation phase objects, RxJS subscriptions, elapsed-time intervals, 30-second download and 60-second initialisation stall timers, and the ASR → diarization → translation sequencing via _startTranscription → handleCompletedTranscription → _startTranslation. All of it lives in the component this conversion deletes.

So the queue is not "a loop over existing services". The per-file orchestration must be extracted into a service that owns one run, with identical behaviour, before anything multiplies it. That extraction is phase 3a and it is the highest-value single task in the plan: it converts roughly 300 lines of page-bound behaviour into the thing the queue drives, and it is independently testable in a way the current code is not.

1. Decisions this plan builds on

Scope Local mode only. Server-backed sessions open the editor pane alone — no left rail, no pipeline.
Bundle One media file plus its annotations. Flat list, no grouping.
Pipeline One global configuration, run as a queue over all loaded media. One language for the set. Existing stage order preserved.
Failure A failed item is marked in the list; the queue continues. Retry is per row.
Reload Bundles whose annotation survived but whose media did not are shown as awaiting media, for the user to re-attach.
Landing page Dropped from the shell. Intro copy, funder and model-developer logos, and the demo link need a new home — an About modal is the cheapest, and it is a content decision, not an engineering one.
Framework Angular 19, staying. Section 9 lists the performance work found along the way and where it belongs.

2. Target architecture

2.1 The bundle record

Three independent axes, deliberately not collapsed into one status field. The mockup's list rows read from exactly these.

interface TrattBundle {
  id: string; // uuid, stable across reload
  createdAt: number;
  source: 'drop' | 'recording' | 'import';
  media: { filename; sizeBytes; mimeType; durationSamples;
          sampleRate; channels; fingerprint };
  residency: 'resident' | 'evicted' | 'decoding' | 'unresolved' | 'decode-failed';
  run: { state: 'idle'|'queued'|'running'|'done'|'failed'|'interrupted';
        stage?: 'decode'|'asr'|'diarization'|'translation';
        progress: number; error?: PipelineError;
        ranWith?: PipelineConfigSnapshot };
  annotation: AnnotationSlice; // today's per-session content, per bundle
  history: WiederHistory; // per-bundle undo, see 2.3
  ui: { editorId; caretSample?; selectedLevel? };
}

residency and run.state must stay separate: a bundle can be awaiting media and hold a finished annotation, which is exactly the post-reload case. ranWith carries provenance — model id, language, stages — and is what the export manifest reports. fingerprint is size plus a hash of the first and last 64 kB, cheap on a 400 MB file, and enough to verify a re-attached file is the one the annotation belongs to.

2.2 State shape

The single currentSession in login-mode.reducer.ts becomes an @ngrx/entity collection. That package is already a dependency, so this adds no new library.

LoginModeState {
  bundles: EntityState<TrattBundle>;
  selectedBundleId?: string;
  pipeline: { config: PipelineConfig; queue: string[]; activeId?: string;
             warmModelId?: string; mode: 'idle'|'running'|'pausing' };
  capacity: { quotaBytes?; usageBytes?; modelBytes; estimatedResidentBytes };
  // currentSession removed
}

Every existing annotation action gains a bundleId in its payload. annotation.selectors.ts gets a selectSelectedBundle at the top and the existing selectors compose off it, which is what keeps the editors' consumption sites nearly unchanged. annotation.store.service.ts already exposes statistics, textInput, status and transcriptString as computed() signals — those re-point at the selected bundle and the editors need no change at all.

2.3 Per-bundle undo

ngrx-wieder wraps the reducer once and keeps one linear patch stack, so a shared history would let an undo in one bundle rewrite another. Because wieder keeps its bookkeeping in the state it wraps, the fix is structural rather than clever: apply undoable() to the per-bundle annotation reducer and let each entity carry its own history, with a higher-order bundles reducer routing each action to its entity by bundleId. Undo and redo then become bundle-scoped by construction, and the global keyboard shortcut resolves against the selection.

This is the subtlest change in the plan and the one that corrupts data silently if wrong. It needs its own spec, written before the refactor: edit A, edit B, switch, undo, assert A is untouched.

2.4 Audio residency — the keystone

Holding every bundle decoded is what crashes the tab. Six hour-long interviews at 48 kHz stereo is on the order of several gigabytes resident, since each bundle keeps the source buffer, the native-rate channel data, and the 16 kHz mono copy the models consume.

The policy: full PCM for the selected bundle plus the two most recent; source blob retained for the rest; re-decode on selection. What makes that invisible to the user is a second artifact — a downsampled min/max envelope computed once at decode time, a few hundred kilobytes, persisted with the bundle. The list rows and the 2D editor paint from the envelope immediately on selection while full PCM re-decodes in the background. Without it, every bundle switch is a visible multi-second stall; with it, eviction is an implementation detail.

This decision must be made before the audio work starts, because it determines whether AudioService holds managers or descriptors. It also makes the capacity indicator honest by construction: resident bytes are bounded by policy, not by how much the user dropped.

2.5 New units
BundleServiceCreate, select, remove, re-attach. The only writer of bundle identity.
AudioResidencyServiceOwns the manager map, eviction policy, envelope cache, re-decode on selection.
PipelineRunnerServiceOne bundle, all stages. Extracted verbatim from login.component.ts.
PipelineQueueServiceFIFO over bundle ids, one in flight, warm-worker lifecycle, failure isolation.
CapacityServiceStorage estimate, model catalogue sizes, resident-bytes estimate.
CatalogueExportServiceMany bundles, chosen converters, one archive plus manifest.
WorkbenchComponentThe two-pane shell. One component, two configurations (local / server).

3. Phase 0 — clear the ground (1 week)

Every item here is a known defect that the conversion would otherwise inherit and multiply, drawn from the existing review findings. Doing them first is cheaper than doing them inside a refactor.

  • Delete the stale app/core/shared/multi-threading/ copies and import from @tratt/utilities / @tratt/ngx-components (D1). The app copies contain the run() promise that never settles when no worker is found (E2); the lib versions have stall recovery. The queue will lean on this code hard.
  • Guard the unguarded audiomanagers[0] and non-null config reads in asr-processing.effects.ts and idb-effects.service.ts (E5, E7) — these are the exact call sites the sweep in phase 2 rewrites.
  • Consolidate the 16 kHz constant declared in four places (D6) and extract the duplicated channel → mono → 16 kHz block shared by transcription and diarization (D7). The runner calls it once per bundle; it should exist once.
  • Delete the new-editor stub (S9). It is declared but never routed, and the editor registry is about to be touched.
  • Write characterisation tests for what phase 2 rewrites: annotation.reducer.spec.ts extended to pin current single-session semantics, and a Dexie fixture seeded at version 0.5 for the migration test to run against.

4. Phase 1 — the shell (1–2 weeks)

Layout only, one bundle, no state change. This is deliberately a boring phase whose purpose is to get the new geometry in front of users while the risky work is still ahead.

  • WorkbenchComponent with the two-pane grid, hosting the existing tratt-dropzone and pipeline options components on the left and the existing dynamic editor host on the right. The editor registry in editors/components.ts supplies the tab set; give its editor: any a real type while you are there.
  • Route it at /workbench alongside the untouched /local, behind a config flag. Both ship; the old path is the rollback.
  • Server-mode variant: same component, left rail suppressed, pipeline providers not registered. Prove the single-configuration approach now rather than discovering later that the shell needs forking.
  • Fastbar, comment field and bottom navigation move in from transcription.component; the detail editor stays a modal.
  • New strings get Transloco keys in both languages; npm run validate:i18n stays green from the first commit.

Done when: a user can drop one file, run the pipeline, edit, and export, entirely at /workbench, with behaviour indistinguishable from /local.

5. Phase 2 — the collection (3–4 weeks)

The real refactor. Sequence within the phase matters, because each step de-risks the next.

# Step Notes
2.1 Entity state Introduce the collection with exactly one entity and a hardcoded selection. Nothing in the UI changes; every selector and effect is re-pointed through selectSelectedBundle. Large diff, no behaviour change — review it as such.
2.2 Per-bundle undo Still one entity, so the new history plumbing is provably equivalent to the old before multiplicity can hide a bug. Spec first.
2.3 Audio registry AudioService gains a Map<bundleId, AudioManager> and a current accessor. The legacy audioManager getter is marked deprecated and made to throw in dev builds when there is no selection, so every stale assumption surfaces loudly instead of returning [0].
2.4 The sweep Roughly 200 call sites, in tranches by directory — editors, then modals, then effects, then tools, then lib consumers — one commit each. Most become audio.current; the ones that must not guess (export, bug report, ASR effects) take an explicit bundleId. Low risk per site, high volume, and it touches files with no coverage today.
2.5 Residency + envelope Eviction policy, envelope computation at decode, envelope-first paint on selection. Test with six long files on a 8 GB machine — this is the step that either holds or does not.
2.6 Dexie 0.6 A bundles table keyed by bundle id, replacing the single key–value record per mode. The upgrade moves an existing local_data session into the first bundle. Must be tested against a real seeded 0.5 database, including the Safari private-browsing quota path the init code already anticipates.
2.7 Multi-file ingest Remove the dropzone's single-file assumption, including the destroy-previous-manager branch. Decode sequentially, not in parallel — decode is memory-spiky and parallel decode is how you crash on drop. Per-file state in the list. Existing size limits (500 MB, WAV 1.9 GB) enforced per file with a clear per-row rejection.
2.8 Unresolved bundles Post-reload rows awaiting media, with per-row re-attach. Match on fingerprint; on mismatch, warn and let the user override — never silently bind an annotation to the wrong audio.
2.9 Recording as a bundle The recording panel is a second ingest path and must create bundles through the same BundleService. The existing recovery banner should offer to restore an interrupted recording into a bundle. Easy to forget; breaks obviously in the field.

Done when: several files can be dropped, each selected and edited independently, undo is bundle-scoped, edits survive reload, and unresolved bundles can be re-attached.

6. Phase 3 — pipeline and capacity (2–3 weeks)

3a. Extract the runner (the critical task)

Move the orchestration out of login.component.ts into PipelineRunnerService: one bundle in, stage events out, all existing behaviour preserved — the ASR → diarization → translation sequence, the graceful degradation when diarization fails (already isolated in local-offline-transcription.helpers.ts, a useful seam), the 30-second download and 60-second initialisation stall timers, the elapsed-time reporting, and cancel. Progress events land in the store throttled to roughly 4 Hz; dispatching per-chunk progress into NgRx would flood the reducer and, with zone-based change detection, re-render the whole shell on every event.

Ship 3a on its own, still one bundle at a time. The login page's pipeline UI becomes a thin consumer, or is deleted with the page. If phase 3 has to stop early, this is still a strict improvement.

3b. The queue
  • Strictly one item in flight. WebGPU memory makes concurrency a bad trade, and out-of-memory is already a handled error path in diarization. Two-at-a-time for small CPU-only models is a later tuning knob, gated on measurement.
  • Warm worker. Today transcribe() calls cancel() as its first statement and terminates the worker on every exit path, which for a six-file queue means re-loading a 1.2 GB model six times. Add acquire/release refcounting, keep the worker and loaded model alive while the configured model is unchanged, and terminate on model change, explicit stop, idle timeout, and page hide. This is the single largest throughput win in the plan.
  • Failure isolation. Classify errors — decode, model load, GPU out of memory, cancelled, unknown — because the user's next action differs for each. Mark the row, continue the queue, offer per-row retry. Reuse the existing catchError → .fail action convention.
  • Interruption. Queue position persists; a job running when the tab closes comes back as interrupted, not running. Say plainly in the UI that closing the tab ends the run — a six-file queue is a long unattended job and this will happen.
  • Skip rules. Unresolved and already-transcribed bundles are excluded by default, which is why the run button counts ready bundles rather than all of them.
3c. Capacity indicator

Two bars, because the phrase "how much media can I load" conflates two budgets and only one is measurable. Storage comes from navigator.storage.estimate(), polled on mount, after a model download, and after a save; what lives there is cached models plus annotations, and the model figures are real numbers already declared as sizeMb in the transcription options component rather than guesses. Media is never written to storage, which is a privacy property worth stating in the indicator rather than hiding. Working memory is the actual ceiling and can only be estimated: source bytes plus duration × 16 kHz × 4 plus duration × native rate × 4 × channels, summed over resident bundles, against a conservative fixed budget. Label the estimate as an estimate, and warn — do not block — when a drop would push past roughly 80%.

7. Phase 4 — catalogue export (1–2 weeks)

Self-contained and pleasantly cheap, because the pieces exist: twenty converters in @tratt/annotation, a zip-builder.ts, and fflate already a dependency. CatalogueExportService iterates the selected bundles, runs the chosen converters, and streams one archive — stream it rather than buffering, since fifty bundles of output should not sit in memory at once. Layout bundles/<slug>/<name>.<ext> plus a manifest.json carrying bundle id, source filename, duration, sample rate, model, language, stages run, unit counts and app version from the existing build-info script — and a manifest.csv alongside it, because the people who need the catalogue are often not the people who read JSON. The existing single-transcript export modal becomes the one-bundle case of the same code path. Bulk actions in the list — select all, clear finished, remove — land here too.

8. Phase 5 — finish (1 week)

Keyboard model across the new geometry (bundle list navigation, and undo resolving against the selection); focus management when selection changes mid-edit; empty, single and fifty-bundle states all checked; the funder and model-developer logos and intro copy rehomed; and the manual. The manual documents a two-page workflow with screenshots, and build:manual plus check-manual-links exist to keep it honest — budget the rewrite rather than discovering it at release.

9. In-framework performance opportunities

Found while assessing the framework question, kept because they are worth doing on their own terms. The framework migration is dropped; these are what it was reaching for.

Opportunity Where it belongs Note
Throttled progress dispatch Absorb — phase 3a Not optional. Per-chunk progress into NgRx under zone-based change detection re-renders the shell continuously during a run.
OnPush on new components Absorb — phases 1–4 17 of ~90 components have it today. Everything new gets it; the list rows especially, since they update on every progress tick.
Signals for new state Absorb — phase 2 Four files use signals today, and annotation.store.service.ts already exposes computed() views. New selectors follow that idiom rather than adding more BehaviorSubject.
OnPush for the remaining ~70 Separate track Modals and panels. Mechanical, per-component testable, parallelisable with the conversion.
Bundle audit Separate track npm run analyze:tratt exists. Jodit, video.js, Konva, animate.css, angular-animations, hammerjs and Modernizr are lazy-load or removal candidates against a 2 MB initial budget.
Zoneless change detection Defer — after the conversion The largest single win available, and the wrong thing to attempt mid-conversion: it makes every implicit re-render explicit across the whole app. Standalone bootstrap is already in place, so the door is open. Do it against a stable shell, not a moving one.
Profile the viewer redraw Separate track The ~7,300-line audio-viewer subsystem was recently split into renderer, interaction, segments and time-utils services. Now that the seams exist, measure updateAllSegments and the redraw path — that is where interactive slowness actually lives.

10. Risk register

Risk Phase Mitigation and early-warning signal
Memory exhaustion 2.5 Tab crash losing unsaved edits — the worst outcome in the plan. Eviction policy decided before the code, six-long-file test on a modest machine as an acceptance gate, and autosave-before-decode so a crash costs nothing.
Undo leaking across bundles 2.2 Silent corruption, not a crash, so tests must precede the change. Land the plumbing while only one bundle exists.
The 200-site sweep 2.4 Breadth, not depth. The throwing dev-mode accessor converts silent wrong-bundle reads into loud failures; tranche commits keep any single revert small.
Runner extraction regresses ASR 3a Behaviour buried in a component with no tests. Extract with no behaviour change, ship alone, and compare output on a fixed reference recording before and after.
Warm worker holds GPU memory 3b Keeping the model resident trades memory for throughput and can turn into out-of-memory on smaller GPUs. Idle timeout, release on model change and page hide, and a fallback to the current terminate-per-run behaviour if the trade proves bad.
IndexedDB migration 2.6 Users have in-flight sessions in local_data. Test against a seeded 0.5 database; export-before-upgrade as a safety net (dexie-export-import is already a dependency).
Scope creep from the landing page 1, 5 Dropping the page raises real content questions (funders, credits, demo entry). Settle them as content decisions in phase 1, not as layout work in phase 5.
